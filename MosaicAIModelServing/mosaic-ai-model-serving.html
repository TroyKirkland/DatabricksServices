L100What it is

Serverless model inference. Register an MLflow model (or wrap external), create endpoint, get scalable REST API with scale-to-zero, GPU, payload logging, Gateway integration. No clusters/K8s.

  • Serverless: scale-to-zero default.
  • Open: MLflow models, FMAPI, external models.
  • Production: autoscaling, payload tables, traffic split, Gateway.

L200The product surface

  • Endpoint hosts served entities: custom models, agent endpoints, FMAPI (Llama/GPT/Claude/Gemini/etc.), external BYOK models.
  • Compute: CPU sizes or GPU_SMALL/MEDIUM/LARGE; scale-to-zero on/off.
  • Traffic split for canary/A/B.
  • Auth: workspace OAuth U2M/M2M.
  • Payload table = Delta table of req/resp in UC.
  • Unity Gateway optional (rate limit, PII, fallback, smart routing).
  • Batch via ai_query() or mlflow.deployments.predict().

L300Architecture

[Caller] → REST → [Endpoint: routing + auth + (Gateway) + inference container + payload tap] → response
                                                                            ↓
                                                                       Delta payload table

Inference containers managed by Databricks. Cold start when scaled to zero. Provisioned-capacity avoids it. Payload tap lands req/resp in UC.

L400Deep internals

Endpoint lifecycle

  • States: pending → ready → updating → ready.
  • Blue/green updates with health-check rollback.

Compute

  • CPU sizes (Small/Medium/Large), GPU classes (Small/Medium/Large).
  • Scale-to-zero after idle; cold start cost.
  • Provisioned throughput for FMAPI: dedicated tokens/s, no cold start.

Routing

  • Traffic split percentages.
  • Fallback routing via Gateway.

Payload tables

  • Auto Delta table: timestamp/req/resp/latency/status/version/identity.
  • Sampling configurable.
  • Drives MLflow eval / monitoring / agent loops.

Auth + identity

  • OAuth M2M/U2M for callers.
  • Endpoint identity can call UC tables, Vector Search, Lakebase via service credentials.

Unity Gateway integration

  • Rate limits, PII detection, fallback, smart routing, payload logging.
  • Fronts internal endpoints, external models, and agent endpoints.

Performance

  • Cold start: CPU 1–5s; GPU 10–60s; large LLM 30s–2min.
  • Latency floor: hundreds of ms for small; LLMs depend on tokens.
  • Throughput: replicas scale; per-replica concurrency tunable.
  • SSE streaming for LLMs.

Batch

  • ai_query parallelises into endpoint up to concurrency.
  • For huge batches, Spark + in-process model.

Limits / realities

  • Per-replica memory caps; large models need GPU_LARGE.
  • Cold-start unpredictable without provisioned.
  • Payload tables fill fast.
  • Per-endpoint concurrency caps (raise via support).
  • External endpoints inherit provider rate limits.
  • Platform benchmark: >25K QPS with <50ms proxy overhead (model inference adds to this).

Mental model

"Serverless API gateway in front of a model." Custom and hosted models look the same to callers. Choose: scale-to-zero vs provisioned, payload logging, Gateway-or-not.

Anti-patternsWhere you should not use Model Serving

  • Sub-10ms latency. Use in-process inference.
  • Billions-of-rows batch. Use Spark batch in-process.
  • GPU-paid CPU codepaths.
  • Streaming high-rate no-provisioned.
  • Stateful sessions. Endpoints are stateless; store in Lakebase/UC.
  • Direct from run URI. Register to UC first.
  • Per-customer endpoints at thousands of customers.
  • Custom router in front of one endpoint. Use traffic split + Gateway.
  • Endpoints as experiment runners.
  • Sensitive prompts un-redacted in payloads.

WeaknessesWhere it does not do well

  • Cold start without provisioned.
  • Per-endpoint concurrency caps.
  • GPU class scarcity per region.
  • Payload table cost.
  • Limited custom container.
  • SSE proxy timeouts.
  • Limited per-call introspection.
  • Per-region availability gaps.
  • Egress on external calls.
  • Limited startup hooks.
  • External integrations vary.
  • UI versioning UX basic.
