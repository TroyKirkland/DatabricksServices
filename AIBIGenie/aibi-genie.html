L100What it is

Genie is the natural-language interface to SQL data. Data teams configure Genie Agents (bounded UC tables + instructions + example queries + metric views); end users interact via Genie One (browser or mobile); Genie generates SQL, executes on a warehouse, returns results + charts.

  • NL → SQL, scoped to a curated agent.
  • Curated, not "ask anything".
  • Self-serve analytics without SQL knowledge.
  • Genie One + Agents free through Jan 31, 2027; Genie Code (developer AI) pay-as-you-go from July 8, 2026.

L200The product surface

  • Genie Agent (formerly Genie Space): name + warehouse + UC tables/views + metric views + instructions + example query pairs + trusted assets.
  • Instructions: column definitions, business rules, avoidances.
  • Example queries: few-shot NL/SQL pairs.
  • Trusted assets: certified SQL Genie can reuse.
  • Metric Views: UC semantic-layer metrics; improves KPI accuracy.
  • Genie One: end-user conversational interface (browser + iOS/Android mobile).
  • Chat mode API: start-conversation + send-message; returns SQL, results, chart proposal.
  • Agent mode API: stream reasoning + SQL; final report with citations.
  • Permissions: VIEW/EDIT/MANAGE.
  • Dashboards can launch a Genie Agent pre-loaded with context.

L300Architecture

Genie One (user) ──► [Genie LLM]
                          │  context: tables/views, metric views, instructions, examples, trusted assets
                          ▼
                     Generated SQL  →  [SQL Warehouse]  →  Result + chart proposal

Databricks-hosted FM (model managed by Databricks). Generated SQL shown + editable. Warehouse runs with user identity → UC policies apply. Trust score per response.

L400Deep internals

Agent = trust boundary

  • Tables/views/metric views in the agent are Genie's universe.
  • Instructions injected in prompt; prose quality matters.
  • 5–20 example pairs is the sweet spot.
  • Trusted assets preferred over fresh generation.
  • Metric views give Genie pre-defined measure semantics; prefer over raw fact tables for KPI questions.

Generation pipeline

  • Parse question + history.
  • Resolve entities against schemas + instructions.
  • Plan: certified asset reuse → modify → fresh generation.
  • Validate via dry-run.
  • Execute with user identity.
  • Compose answer: chart + summary + rows.

Execution semantics

  • One question = one SQL.
  • Follow-ups can inject filters into prior SQL.
  • Result-cache hits if SQL matches.
  • UC enforces; fail-closed on perms.

Trust signals

  • Trusted-asset use → high confidence.
  • Unfamiliar columns → lower confidence + disclosure.
  • Multiple draft attempts shown.

Multi-turn handling

  • Per-user per-space conversation state.
  • Follow-up resolution is heuristic.

Conversation API (Chat mode + Agent mode)

  • Chat mode: POST /api/2.0/genie/spaces/{space_id}/start-conversation + send-message. Returns SQL, query ID, results, chart proposal. Paths still use spaces resource name.
  • Agent mode: stream reasoning + SQL results; final report with citations. Newer, for agentic apps.

Curation lifecycle

  • Monitor thumbs-down → add examples / instructions → promote good queries to trusted assets.
  • An agent is never "done" — quality is continuous curation, not setup.

Limits / realities

  • ~20–30 tables per space ceiling for quality.
  • Multi-table joins hard without supporting views.
  • Cohort / window patterns need examples.
  • Hallucination still possible.
  • Cost = LLM call + warehouse query per question.

Mental model

"NL → SQL bounded by curation." The product is the Agent + instructions + metric views + certified queries, not the model.

Anti-patternsWhere you should not use Genie

  • Ask-anything sprawling agent. Build domain-focused agents.
  • Replace dashboards entirely. Complement, don't replace.
  • DBA tool. Not for DDL.
  • Real-time decisions. Multi-second latency.
  • Behind a customer app expecting deterministic SQL.
  • Uncurated data.
  • No steward. Agents rot.
  • Cross-agent federation.
  • Compliance-grade auditing via NL.
  • Long-form analytical reports. Use notebooks/AI functions.

WeaknessesWhere it does not do well

  • Quality = curation.
  • Complex multi-table joins.
  • Stateful follow-up drift.
  • Occasional hallucinated columns.
  • Limited self-correction.
  • No first-class explanation.
  • Per-user RLS → per-user variability.
  • Opaque per-question cost at scale.
  • Basic chart proposals.
  • Underlying model evolves.
  • No native A/B of instruction changes.
  • Cryptic column names defeat it.
