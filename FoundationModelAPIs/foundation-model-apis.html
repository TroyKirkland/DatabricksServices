L100What it is

Databricks-hosted AI models — open-source and commercial from OpenAI, Anthropic, Google, Meta, xAI, DeepSeek, and others. Served via Mosaic AI Model Serving with two billing modes. LLMs (including multimodal), embeddings, rerankers — Databricks manages billing and infra for the full catalog.

  • Hosted models: OpenAI GPT-5/6; Anthropic Claude (Haiku/Sonnet/Fable/Opus); Google Gemini 3.x; Llama 4; xAI Grok; DeepSeek V4; Qwen3; GTE/BGE embeddings.
  • Two billing modes: pay-per-token vs provisioned throughput.
  • Same surface as any Model Serving endpoint.

L200The product surface

  • Models: OpenAI GPT-5/6 (text+image); Claude Haiku/Sonnet/Fable/Opus 4.x–5.x (text+image); Gemini 3.x Flash/Pro (text/image/video/audio); Llama 4 Maverick + Llama 3.x (text±image); xAI Grok, DeepSeek V4, Qwen3, Zhipu GLM, Kimi; GTE/BGE + Qwen3 embeddings; rerankers. DBRX and Mistral no longer active; Gemini 2.5 retired Oct 2026.
  • Pay-per-token (shared infra; global rate limits).
  • Provisioned throughput (dedicated capacity; no cold start).
  • Stable endpoint names (e.g., databricks-meta-llama-3-x-instruct).
  • Optional Unity Gateway routing (policy, smart routing, payload logging).
  • OAuth + UC on the endpoint.

L300Architecture

[Caller] → [FMAPI endpoint = Model Serving endpoint]
              ├ Pay-per-token → multi-tenant pool (cold start hidden)
              └ Provisioned   → dedicated replicas
              ↓
           [Token meter] → system.serving.endpoint_usage
              ↓
           [Response]

Pay-per-token shares Databricks infra; provisioned commits to tokens/s. Gateway adds policy + payload + fallback.

L400Deep internals

Pay-per-token

  • Per million tokens billing (model-specific).
  • Global rate limits; bursts can fail.
  • Warm pool hides cold start.
  • Best for prototyping / low-volume / bursty.

Provisioned throughput

  • Reserve tokens/s; per replica-hour cost.
  • No cold start; latency stable.
  • Best for steady-state production / strict SLAs.

Performance

  • TTF token: 8B sub-second; 70B+ seconds.
  • Output rate: tens–hundreds of tokens/s per replica.
  • Provisioned scales linearly within model-class limits.

Model lifecycle

  • Databricks introduces/retires models with notice.
  • Stable endpoint name + version suffix.
  • Region-gated rollouts possible.

Embeddings

  • databricks-gte-large-en = 1024-dim text embeddings; databricks-bge-large-en as alternative.
  • Qwen3-Embedding-0.6B: compact multilingual option (Public Preview).
  • Pay-per-input-token; provisioned for high-volume indexing.

Function calling

  • Most families (Llama 3.x/4.x, OpenAI GPT-5/6, Claude, Gemini) support function/tool calling via the chat API.
  • ai_query with structured outputs in DBSQL.

Streaming

  • SSE for chat.
  • End-of-stream guardrails via Gateway.

Cost attribution

  • system.serving.endpoint_usage tokens.
  • Join system.billing.list_prices for $/token.
  • Payload tables (Gateway) for per-call.

Limits / realities

  • Pay-per-token rate limits per-workspace + global.
  • Provisioned commits aren't instant-undoable.
  • Multimodal availability uneven.
  • Region availability uneven.
  • Tokens = input + output; long prompts + verbose = expensive.
  • Context windows per-model.

Mental model

"OpenAI-style hosted LLMs governed inside Databricks." Pay-per-token for prototypes; provisioned for production. Building block for Agent Bricks, Genie, ai_query.

Anti-patternsWhere you should not use FMAPI

  • Sub-100ms hard latency.
  • Pay-per-token at steady high-volume. Switch to provisioned.
  • Provisioned for bursty. Wasted capacity.
  • Long-context without verifying window.
  • Assuming uniform multimodal support. Text+image is mainstream; video/audio = Gemini only; image generation = select Gemini models. Verify on supported-models page.
  • FMAPI as a model registry.
  • Expecting bigger compute to speed token rate.
  • No payload sampling on Gateway.
  • Single-provider with no fallback.
  • Deterministic outputs.

WeaknessesWhere it does not do well

  • Curated model selection.
  • Pay-per-token rate-limit failures.
  • Provisioned commits non-instant.
  • No in-place fine-tuning.
  • Region gaps.
  • Cost prediction tooling basic.
  • SSE + structured output edge cases.
  • Model upgrade behaviour drift.
  • Limited system-prompt customisation.
  • Multimodal coverage varies by modality. Text+image mainstream; video/audio input Gemini-only; image generation model-specific.
  • Tokenizer mismatch surprises.
  • Latency variability under load.
