L100What it is

Unity Catalog is Databricks' unified governance plane. One metastore per region per account governs tables, views, models, volumes, features, functions, MVs, streaming tables, external sources — across all workspaces. Permissions, lineage, audit, discovery — all UC.

  • One metastore, many workspaces.
  • 3-level namespace: catalog.schema.object.
  • Fine-grained: GRANT, row filters, column masks, ABAC.
  • First-class lineage + audit.

L200The product surface

  • Metastore (1 per region per account).
  • Catalog → Schema → Object.
  • Object types: tables, views, MVs, STs, volumes, functions, models, ML features, connections, foreign catalogs, clean rooms, managed and foreign Iceberg tables (GA May 2026), secrets (catalog.schema.secret, GA August 2026).
  • External locations + storage credentials.
  • Permissions with inheritance.
  • Row filters + column masks (SQL UDFs at read time).
  • ABAC: tag-based policies.
  • Lineage table- + column-level.
  • System tables: billing, audit, lineage, query history.
  • Catalog Explorer; comments + tags; AI-generated descriptions.
  • Delta Sharing + foreign catalogs (Federation).

L300Architecture

Account console
       ↓
┌────────────────┐
│ UC Metastore   │ ── catalog/schema/object metadata, credentials, grants, policies, lineage, audit
└────────────────┘
   ▲          ▲
  W1         W2  ... (workspaces attach)
   │          │
queries from clusters / warehouses / jobs / apps
   ↓
UC enforces: permission, row filter, column mask, ABAC
   ↓
Storage credentials → cloud object storage

Metastore = source of truth. Every read/write goes through UC permission checks before storage I/O. Storage credentials bridge to cloud IAM. Lineage emits async events; audit logs every operation.

L400Deep internals

Object model

  • 3-level naming; case-insensitive on access, case-preserving on creation.
  • Stable UUIDs; renames preserve ID + lineage.
  • Comments + tags first-class.

Permission model

  • SELECT, MODIFY, USE CATALOG/SCHEMA, CREATE TABLE, EXECUTE, BROWSE, READ/WRITE VOLUME.
  • Fine-grained DML privileges (Beta, DBR 18.1+): INSERT, UPDATE, DELETE separate from MODIFY — for least-privilege write grants.
  • READ METADATA (GA): read-only visibility into grants, row filters, column masks, and ABAC policies for auditors.
  • Inheritance: USE on parents required.
  • Grants to groups/SPs/users.
  • Role-Based Access Control (RBAC) (GA August 2026): users can assume a named role applying only that role's permissions.
  • Owner has full perms + grant.

Row filters + column masks

  • SQL UDF returning bool (filter) or transformed value (mask).
  • Evaluated on every read; keep cheap.
  • Use current_user() / is_account_group_member().

ABAC

  • Policies over tags on objects + identities.
  • Metastore-level attachment (Beta): one policy across all catalogs in the account.
  • DENY policies (Beta): block MANAGE ACCESS CONTROL on supported securables.
  • Identity Attributes (Beta Aug 2026): up to 9 IdP attributes (dept, country, etc.) on users, usable in column-masking policies via SCIM 2.1.
  • AI asset coverage (Beta Aug 2026): applies to model services, model provider services, MCP services, and agent services.
  • Scales beyond per-table grants; combines with row filters / column masks.

Storage credentials + external locations

  • Credential wraps cloud IAM identity.
  • External location = (URL, credential); UC fronts cluster IAM.

Lineage

  • Table + column from UC queries; visible in Catalog Explorer + system tables.
  • Model service lineage: tracks data assets feeding served models (model services and external model providers).
  • External asset lineage: upstream sources (Salesforce, MySQL) and downstream tools (Tableau, Power BI) linkable for end-to-end graphs.
  • Async, can have gaps; stops at foreign edges.

System tables

  • system.access.audit, access.table_lineage, access.column_lineage
  • system.billing.usage, billing.list_prices
  • system.compute.warehouses / clusters
  • system.query.history — query text masked by default (Aug 2026); databricks_pii_access group required for unmasked.
  • system.workflow.*
  • system.tags.governed_tags (Beta July 2026) — governed tag keys across account.

Volumes

  • Non-tabular data; path /Volumes/cat/sch/vol/....
  • READ/WRITE/MANAGE VOLUME perms.

Multi-workspace

  • One metastore serves many workspaces.
  • Workspace bindings allow dev/prod separation.
  • Catalog isolated or shared.

Managed vs external

  • Managed: UC owns files; PO applies.
  • External: cloud lifecycle yours.

Limits / realities

  • One metastore per region per account.
  • HMS legacy migration is a project.
  • Grants propagate in seconds — CI may need retry.
  • 100K+ tables → Catalog Explorer slows.
  • ABAC complexity needs tag discipline.

Mental model

"IAM + lineage + audit for the lakehouse." Biggest design decision: catalog/schema taxonomy — hard to undo at scale.

Anti-patternsWhere you should not use UC (or avoid these designs)

  • Skipping UC on new workspaces.
  • One giant catalog with thousands of schemas.
  • Per-table grants for hundreds of users. Use groups/ABAC.
  • Row filters that join other tables. Use identity predicates.
  • Environment-suffix catalogs. Use workspace bindings.
  • External tables when managed works.
  • SP-only access. Mix groups for discoverability.
  • Blob columns. Use UC Volumes.
  • Cross-region single metastore.
  • UC as documentation only. It's enforcement.

WeaknessesWhere it does not do well

  • Cross-region multi-metastore management.
  • ABAC complexity.
  • Row filter / column mask perf cost.
  • Permission propagation not instant.
  • Lineage async + gappy.
  • HMS migration effort.
  • Basic credential rotation tooling.
  • Tagging needs governance.
  • Catalog Explorer scales OK, not great.
  • System tables retention finite.
  • Federation lineage limited.
  • Workspace vs account identity confusion.
