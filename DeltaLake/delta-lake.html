L100What it is

Delta Lake is an open-source transactional storage format on Parquet. ACID transactions, schema enforcement, time travel, MERGE/UPDATE/DELETE, stats-based skipping — without giving up the open format.

  • ACID on object storage: atomic commits, isolation via the transaction log.
  • Open format: Parquet + JSON+checkpoint log; readable by any Delta reader.
  • Substrate of the lakehouse: every Databricks table is Delta unless stated otherwise.

L200The product surface

  • Table types: managed, external, shallow/deep clones, streaming tables, MVs.
  • Write: SQL INSERT/MERGE/UPDATE/DELETE/COPY INTO and DataFrame.
  • Schema enforcement: writes fail on mismatch unless mergeSchema.
  • Time travel: VERSION AS OF / TIMESTAMP AS OF; bounded by VACUUM.
  • CDF: per-row change events via table_changes(...).
  • Optimisation: OPTIMIZE, ZORDER (legacy), liquid clustering, deletion vectors, Predictive Optimization.
  • Constraints: NOT NULL, CHECK.
  • Column mapping: rename/drop without rewrite.
  • Row tracking: delta.enableRowTracking = true; stable _metadata.row_id + _metadata.row_commit_version per row. GA since DBR 14.0.
  • UniForm: Iceberg metadata (IcebergCompatV2) alongside Delta. Iceberg-only; Hudi support removed.

L300Architecture

Delta table directory
├── _delta_log/
│   ├── 00000000000000000000.json   (commit 0)
│   ├── ...
│   ├── 00000000000000000010.checkpoint.parquet
│   └── _last_checkpoint
├── part-00000-uuid.snappy.parquet
└── ...

Transaction log = database. Each commit is a JSON file of actions: Protocol, Metadata, Add (file+stats), Remove (tombstone), Txn (idempotency), CommitInfo. Periodic checkpoint Parquets avoid full replay. Reads: latest checkpoint + tail of JSON commits → file pruning via stats + partitions. Writes: optimistic concurrency — retry on conflict. Maintenance: OPTIMIZE (compact), VACUUM (delete old files), liquid clustering. Photon reads stats, prunes, vectorises Parquet, applies deletion vectors.

L400Deep internals

Transaction log in depth

  • Commit files 00…json; checkpoints every 10 commits by default (delta.checkpointInterval). Multi-part v2 checkpoints for huge tables.
  • _last_checkpoint pointer avoids scanning all logs.
  • Protocol versions: minReaderVersion / minWriterVersion. Some features (DV, column mapping, type widening) bump them.
  • Idempotent writes via txnAppId + txnVersion.

Add / Remove / Stats

  • Add: path, partitionValues, size, dataChange, tags, stats (min/max/null per column) — drives pruning.
  • Remove: tombstone; physical delete only after VACUUM retention.
  • OPTIMIZE emits Add + Remove with dataChange=false so streams skip.

Concurrency model

  • Optimistic concurrency. Loser retries at v+2.
  • Conflict on file-touch overlap, not whole table.
  • Heavy MERGE benefits from clustering + DV + partitioning to minimise overlap.

Deletion vectors

  • DV files referenced by Add.deletionVector.
  • DELETE/UPDATE/MERGE write DV instead of rewriting Parquet.
  • Photon applies natively; some non-Databricks readers don't yet.
  • OPTIMIZE periodically compacts DVs back into rewritten Parquet.

Liquid clustering

  • CLUSTER BY (col1, col2) at create.
  • Writes routed to clusters; small clusters merge.
  • Add/remove cluster columns = metadata-only (unlike PARTITIONED BY).

Column mapping

  • id mode (field IDs) or name mode (logical→physical).
  • Required for RENAME/DROP COLUMN; bumps reader protocol.

Predictive Optimization

  • UC managed only (not external tables). Auto-runs OPTIMIZE/VACUUM when worthwhile.
  • Enabled by default for accounts created on or after November 2024.
  • Typically cheaper than naive nightly maintenance.

Row tracking

  • Enabled per-table via delta.enableRowTracking = true.
  • Stable _metadata.row_id (survives MERGE/UPDATE) + _metadata.row_commit_version for row-level lineage.
  • Enabling on existing tables requires pausing concurrent writes; bumps writer protocol. GA since DBR 14.0.

Change Data Feed

  • Enabled per-table; writes per-row change records under _change_data/.
  • Read via table_changes('cat.sch.tbl', startV, endV).
  • Feeds APPLY CHANGES INTO downstream.

UniForm

  • Same Parquet; Iceberg metadata (IcebergCompatV2) generated atomic with Delta commit. Hudi support removed; Iceberg-only.
  • OpenSharing: D2O recipients can read via Iceberg REST Catalog API (Public Preview, Runtime 16.1+).
  • VACUUM now deletes untracked metadata/ files while keeping live Iceberg metadata (Runtime 17.2+).
  • Trade-off: small metadata cost; deletion vectors with certain configs limit Iceberg reader visibility.

Limits / realities

  • High-cardinality partition columns = footgun. Use liquid clustering.
  • Time-travel vs VACUUM tension; default 7-day retention.
  • Cross-region writes pay commit-PUT latency.
  • Stats only on first 32 columns by default — raise delta.dataSkippingNumIndexedCols or reorder.
  • Streaming reads with ignoreChanges=true still see deletes.

Mental model

"Parquet with a transaction log on the side." The log gives you ACID, time travel, CDF, concurrency. Everything else (clustering, DV, UniForm, PO) is built on it. Mastery = log mechanics + optimistic concurrency + protocol management.

Anti-patternsWhere you should not use Delta Lake

  • Sub-ms key-value lookups. Use Lakebase or a KV store.
  • Tiny frequent point updates. Batch them.
  • High-cardinality partition columns. Use liquid clustering.
  • Substitute for OLTP. No row-level locking, no FK.
  • Many writers on overlapping files. Write amplification. Cluster or serialise.
  • External tables without a maintenance owner. Predictive Optimization doesn't cover them.
  • Pure append + never-read. Plain Parquet is cheaper.
  • New tables with PARTITIONED BY. Use liquid clustering.
  • Time travel as backup. Bounded by retention; use clone or external backup.
  • Huge blobs in columns. Use UC Volumes.

WeaknessesWhere it does not do well

  • Tiny-commit explosion. One-row-per-commit destroys read performance.
  • Default stats on 32 cols. Wide tables need tuning.
  • MERGE under contention. Overlapping partitions retry.
  • Renames need column mapping. Bumps protocol.
  • DV not universal in external readers. Use UniForm or rewrite-OPTIMIZE.
  • VACUUM safety is on you. Low retention destroys time-travel + active reads.
  • Cross-region commit latency.
  • Protocol coupling. Enabling new features breaks old engines.
  • Audit lives in UC. Outside UC, only CommitInfo.
  • Z-order legacy. Migrating to clustering needs care.
  • Type widening scope is bounded. GA since DBR 15.4 LTS, but only defined widening paths supported; others still require rewrite. Protocol bump; readers need DBR 15.4+ LTS minimum.
  • Big checkpoints for huge tables. Multi-part v2 needs enablement.
