L100What it is

Eval-driven agent builder. Pick a template (Knowledge Assistant / Genie Agent / Multi-Agent Supervisor), point at data; Databricks generates baseline + eval harness. Iterate via evals + labelled traces.

  • Use-case templates, not blank-slate agent builder.
  • Eval-first: every agent ships with a starter eval set.
  • UC + MLflow + Model Serving + Vector Search wired together.

L200The product surface

  • Knowledge Assistant: RAG over UC docs / volumes / AI Search indexes. Instructed Retriever approach with citation tracking.
  • Genie Agent: NL→SQL agent surface backed by a curated Genie Space.
  • Multi-Agent Supervisor: router LLM + child agents (KA / Genie Agents / agent endpoints / UC functions / MCP servers / custom agents).
  • Agent Bricks CLI (Beta): scaffold, run, and deploy custom code agents from CLI; managed memory, sessions, tools, MLflow tracing wired.
  • Evaluation harness with built-in scorers + custom.
  • One-click deploy to Model Serving (ChatAgent/ResponsesAgent, SSE streaming).
  • Optimization loop: suggested prompt/retrieval/example changes.
  • UC-tracked components.

L300Architecture

UC data → Agent Bricks pipeline (KA / Genie / MAS) → UC registered model → Model Serving endpoint → callers
                                                                                     ↓
                                                                             MLflow traces + payload tables + eval

Components are Databricks-managed but visible (Vector Search index, endpoint, MLflow run). Eval is in-the-loop.

L400Deep internals

KA pipeline

  • Ingest UC tables/volumes → chunk → embed (FMAPI default) → Delta Sync Vector Search index → hybrid retrieve → LLM generate.

Genie integration

  • Genie Conversation API exposed as a tool.
  • Genie governance/RLS applies.

Multi-Agent Supervisor

  • Router LLM picks child each turn.
  • Children: KA / Genie Agents / agent endpoints / UC functions / MCP servers / sub-MAS / custom agents.
  • MCP (Model Context Protocol) servers plug in as standardised tool sources; any MCP-compatible server works.
  • Supervisor holds state; children stateless w.r.t. each other.

Agent Bricks CLI (Beta)

  • Code-first alternative to GUI templates; scaffold + run + deploy custom agents.
  • Managed memory, session handling, tool declarations in config.
  • MLflow tracing auto-wired on deploy.
  • Beta: breaking changes likely; not yet for production-critical agents.
  • Upgrade path: GUI templates → CLI → full LangGraph.

Evaluation

  • Auto-seeded eval dataset; expanded by labeling.
  • Scorers: Correctness, RetrievalGroundedness, Safety, Guidelines + custom @scorer.
  • Eval runs = MLflow runs.
  • Production traces sample → label → expand dataset.

Optimization loop

  • Detects failure patterns, suggests prompt/retrieval/example tweaks.
  • Suggestions vetted against eval before apply.

Deployment

  • Endpoint with ChatAgent or ResponsesAgent schema; SSE streaming.
  • Payload table for live traffic; traffic-split for canary.

Auth + identity

  • Endpoint identity has UC + VS + Genie + endpoint service credentials.
  • Caller workspace OAuth.

Limits / realities

  • Opinionated; deep customisation = drop to MLflow + LangGraph.
  • Eval scorer costs add up.
  • MAS fan-out costs per-call.

Mental model

"Templates + eval loop + Databricks primitives wired." Value is opinionated patterns + tractable iteration, not raw flexibility.

Anti-patternsWhere you should not use Agent Bricks

  • Bespoke multi-step agents. Use LangGraph directly.
  • Edge / low-latency. Multi-call agents = seconds.
  • Use cases that don't fit templates.
  • Codegen agents.
  • Consumer-scale high-volume API. Per-call cost dominates.
  • Domains without measurable correctness.
  • Uncurated Genie spaces in MAS.
  • Sub-500ms decisions.
  • High-stakes decisions without HITL.
  • One-time extraction. Use a notebook.

WeaknessesWhere it does not do well

  • Opinionated template ceiling.
  • Eval cost.
  • MAS fan-out cost.
  • Implicit multi-turn state.
  • Trace pattern analysis manual.
  • Limited tool ecosystem.
  • Suggestion quality depends on eval coverage.
  • Multi-provider model mixing complexity.
  • Long histories balloon token cost.
  • KA quality bounded by retrieval.
  • Inherits Genie curation rot.
  • Versioning composition rough.
