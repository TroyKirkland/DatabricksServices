L100What it is

AI/BI Dashboards is Databricks' native dashboarding. Define datasets (SQL against UC), drop widgets, parameterise, publish. The BI layer that lives inside Databricks.

  • Lakehouse-native: UC tables direct.
  • Modern dashboarding: cross-filter, parameters, drill-down, Genie integration.
  • Embedded sharing: viewers without workspace access; PDF/image subscriptions.

L200The product surface

  • Dataset: named SQL query against UC SQL warehouse, or a UC table/view/metric view; multi-statement queries supported. Metric views first-class; use the MEASURE aggregate. Local metric views can be scoped to the dashboard without publishing to UC.
  • Custom Calculations: derived columns applied on top of a dataset without modifying source SQL.
  • Widgets: line/bar/area/pie/scatter/funnel, counter, table, pivot, filter, text.
  • Parameters: bind to SQL via :param; drive cross-filter / drill.
  • Pages: multi-page dashboards.
  • Draft vs Publish: publish freezes viewer copy.
  • Genie integration: link a Genie Agent (formerly Genie Space) for NL follow-ups.
  • Subscriptions: scheduled email PDF/image/link.
  • Embedding: account-level viewers (paid).
  • DAB-deployable assets.

L300Architecture

[UC tables/MVs/STs] ──► [SQL Warehouse] ──► [Datasets] ──► [Widgets render in browser]
                                                            │
                                                            ├─ Result cache (warehouse)
                                                            ├─ Page cross-filter
                                                            └─ Genie space (optional)

All queries run on a chosen SQL warehouse; serverless preferred. Result cache drives fast repeat loads. Permissions: VIEW/EDIT/MANAGE; query identity is "as viewer" or "as publisher".

L400Deep internals

Datasets + execution

  • SQL + optional LIMIT (or UC table/view/metric view); multi-statement queries supported; widgets reference datasets; datasets reference UC.
  • Custom Calculations: add derived columns to a dataset without touching source SQL.
  • Publish snapshots SQL; draft edits invisible until republish.
  • Large results sampled to widget capacity.

Query identity

  • As viewer: per-user identity, UC row/column policies apply, audit tagged.
  • As publisher: single identity, easier, weaker for RLS.

Parameters + cross-filter

  • Text/number/date/dropdown/multi-select. Defaults can be current_user() etc.
  • Cross-filter injects predicates implicitly; needs matching column.
  • URL query string for shareable parameterised links.

Caching layers

  • Warehouse result cache (query + params + viewer identity).
  • Browser/page state (not durable).
  • Subscription snapshots (delivered artifact).

Subscriptions

  • PDF / image / link; identity = subscriber or publisher.
  • Retry semantics limited.

Genie integration

  • Linked Genie Agent (formerly Genie Space) gets dashboard context.
  • Same warehouse.

Embedding

  • Account-level viewers (paid) for external users.
  • iframe via SSO or signed-URL flow.

Performance

  • First load = warehouse cold (5–15s) + slowest dataset.
  • Repeat loads cached.
  • Heavy dashboards (20+ widgets) slow; optimise with MVs.

Limits / realities

  • ~50 widgets/page soft cap.
  • Limited custom viz vs Tableau/PowerBI.
  • Drill-through via parameters only.
  • No write-back / cell edit.
  • Subscriptions static.

Mental model

"BI on UC + a serverless warehouse." Lighter than Tableau, deeply integrated with lakehouse + Genie. Best for focused lakehouse-centric dashboards with governance in one place.

Anti-patternsWhere you should not use AI/BI Dashboards

  • Complex enterprise BI with bespoke visuals.
  • Sub-second real-time monitoring. Use Grafana.
  • Write-back / data entry. Use a Databricks App.
  • Heavy custom viz.
  • Printable / paginated reports.
  • Pivot-table-heavy financial modelling.
  • Hundreds of KPI tiles. Warehouse thrash.
  • Ad-hoc analyst sandbox. Use SQL editor + Genie.
  • One-off Slack share. Paste a result.
  • Customer-app embedding without account viewers.

WeaknessesWhere it does not do well

  • First-load cold-start latency.
  • No deep custom viz.
  • Cross-dashboard drill requires URL params.
  • Subscriptions static.
  • Limited param UI.
  • Versioning via DABs only.
  • Cross-filter inference surprises.
  • Identity model trade-offs.
  • Excel export OK, not great.
  • No comments / annotations.
  • Hard cost attribution per dashboard.
  • MV staleness surfaces without warning.
