L100What it is

Photon is Databricks' native C++ vectorized execution engine inside Spark workers. Takes over query execution for supported operators; falls back to JVM Spark otherwise. Up to 5× price/performance on TPC-DS benchmarks; no code changes required.

  • Native, vectorized: C++ + SIMD on Arrow-style columnar buffers.
  • Drop-in: enabled per SKU.
  • Partial coverage: mixed plans are normal.

L200The product surface

  • No user API.
  • Enabled on: Photon DBR, Serverless/Pro SQL Warehouses, Serverless Jobs, Serverless LDP.
  • Billing: higher DBU rate; net cost typically lower due to speedup.
  • Workloads: Spark SQL, DataFrame, Delta r/w, Lakeflow pipelines, stateless Structured Streaming (Delta, Parquet, Kafka, Kinesis), feature engineering. Accelerated Parquet writes for Delta and Apache Iceberg. Stateful streaming not supported.
  • Observability: Spark UI Photon highlights; EXPLAIN FORMATTED shows PhotonResultStage/PhotonScan.

L400Deep internals

Operator coverage

  • Photonised: scan (Delta/Parquet), filter, project, hash agg, joins, sort, limit, window (subset), shuffle (partial), primitive expressions. Also: Parquet writes for Delta and Apache Iceberg.
  • Not Photonised: Python row-UDFs, R UDFs, some non-Delta sources, decimal/string edge cases, stateful streaming operators.
  • Coverage grows per DBR release.

Mixed-plan cost

  • Photon → JVM crossing materialises Arrow batches; non-trivial overhead.
  • Use pandas UDFs or SQL/Spark expressions to keep Photon end-to-end.

Memory + CPU

  • Off-heap memory separate from JVM heap.
  • Spill to disk in Photon-native format.
  • SIMD: AVX2/AVX-512 on Intel, NEON on Graviton.

Predicate pushdown + stats

  • Reads _delta_log stats; aggressive column pruning, dictionary filtering, predicate vectorisation.
  • Deletion vectors applied inside native scan.

Shuffles

  • Partially Photonised; wire format Spark-compatible.
  • PhotonShuffleExchangeExec markers indicate participation.

Expressions

  • Most arithmetic / comparison / string / date Photonised.
  • Locale-sensitive / decimal-precision edge cases escalate to JVM.
  • Window functions Photonised; skew problems unchanged.

Streaming

  • Accelerates stateless Structured Streaming micro-batches: aggregations, projections, filters, sinks for Delta/Parquet/Kafka/Kinesis.
  • Stateful streaming not supported — stateful operators run on JVM Spark regardless of Photon enablement.
  • Lakeflow serverless pipelines lean on Photon for stateless throughput.

Limits / gotchas

  • No Python row-UDF acceleration.
  • Photon DBU higher; scan-heavy low-compute workloads may net more expensive.
  • Subtle semantic differences vs JVM Spark (decimal, error messages).
  • No way to force pure-JVM in mixed plans without disabling Photon.
  • OSS Spark features not always Photon-supported on day one.

Mental model

"C++ engine quietly executing SQL on Arrow buffers with SIMD." Photon takes what it can; rest stays JVM; boundary costs. Win by writing SQL/DataFrame and avoiding Python row-UDFs.

Anti-patternsWhere Photon doesn't pay off

  • Workloads dominated by Python row-UDFs.
  • R / Scala UDFs that escape engine.
  • Pure file-listing / metadata work.
  • Tiny fast queries on serverless warehouse.
  • Massive unfixed skew.
  • CSV/JSON-heavy reads. Less Photonised.
  • Heavy decimal-edge logic.
  • Bad query design. Engine won't save you.
  • All-UDF streaming.
  • Single-node ML training. Not the right tool.

WeaknessesWhere it does not do well

  • Python row-UDFs. Hard ceiling.
  • Mixed-plan overhead.
  • Partial operator coverage.
  • Higher DBU rate.
  • Subtle semantic diffs vs JVM Spark.
  • Closed-source, no extension.
  • Opaque profiling.
  • No GPU codepath.
  • Few tuning knobs.
  • Tied to DBR version.
  • Some Delta features lag.
  • Stateful streaming not supported. Stateful operators run on JVM Spark.
