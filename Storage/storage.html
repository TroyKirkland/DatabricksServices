L100What it is

Storage on Databricks is cloud object storage (S3 / ADLS Gen2 / GCS) governed by Unity Catalog and accessed almost always through Delta Lake. No Databricks-owned disk array. Bytes live in your cloud (or the metastore's managed root) as Parquet; Delta's log makes them transactional; UC decides who reads or writes.

  • Bring your own bucket — files sit on cloud object storage.
  • Delta is the default — every table is Delta unless you opt out.
  • Governance is centralized in UC — one metastore per region; catalog.schema.object namespace; uniform permissions and lineage.

L200The product surface

Three storage abstractions you actually create:

  • Tables (managed | external | streaming | materialized view | foreign | shared) — catalog.schema.table
  • Volumes (managed | external) — files at /Volumes/<cat>/<sch>/<vol>/...
  • Specialised assets — registered models, functions, vector indexes

Plumbing in UC:

  • Storage credential — wraps IAM role / managed identity / GCP SA.
  • External location — credential + URI prefix.
  • Managed storage root — default for managed tables/volumes.

Table flavors: managed (UC owns lifecycle) · external (UC points at your path) · streaming/MV (pipeline-managed) · foreign (Lakehouse Federation) · share/recipient (Delta Sharing).

Write APIs: SQL (INSERT/MERGE/COPY INTO), DataFrame (.write.format("delta")), Auto Loader for incremental, Lakeflow Connect for managed source-to-Delta.

L300Architecture

           ┌──────────── Unity Catalog ────────────┐
           │  Metastore → Catalog → Schema → {       │
           │    Tables, Volumes, Models, ...,        │
           │    External locations → Storage creds   │
           │  }                                      │
           └──────────┬──────────────────┬───────────┘
            permission│              path→cred
                      ▼                  ▼
        ┌─── Compute (Spark/Photon, SQL, Serverless) ───┐
        │ reads _delta_log → prunes via stats → opens  │
        │ Parquet → applies DVs + row filters/masks    │
        └──────────────────────┬───────────────────────┘
                               ▼
                  ┌──────────────────────┐
                  │ Cloud object store   │  S3 / ADLS / GCS
                  │ _delta_log/, part-*  │
                  └──────────────────────┘

Three layers, top down:

  • Logical (UC) — names, permissions, lineage, audit.
  • Format (Delta) — _delta_log/ = the database; JSON commits + checkpoints; Add/Remove/Metadata/Protocol actions; stats power pruning.
  • Physical (cloud storage) — Parquet, deletion-vector files, _change_data/.

Read path: UC checks permission → short-lived cred → read _last_checkpoint + log tail → snapshot → prune via stats + partitions/cluster → open Parquet → apply DVs + row filters/column masks.

Write path: optimistic concurrency. Read version v, attempt commit at v+1; if log file exists, retry on new snapshot. Conflicts at file level, not row level.

Maintenance: OPTIMIZE compacts; liquid clustering routes writes; DVs soft-delete; VACUUM physically removes past retention; Predictive Optimization runs OPTIMIZE/VACUUM/ANALYZE automatically on UC managed tables.

Governance overlay: UC injects row filters / column masks into the logical plan before files are read — engines can't bypass. Audit/lineage in system.*.

L400Deep internals

Cloud object store characteristics that matter

  • S3 / ADLS Gen2 / GCS are read-after-write consistent — Delta depends on this.
  • S3 commit atomicity via conditional PUT (if-none-match) on the next JSON log file; loser gets 412, retries.
  • Per-prefix throughput limits (S3 ~3,500 PUT / 5,500 GET per prefix per sec baseline). Hot _delta_log/ on extreme write rates is a bottleneck.
  • Standard tier for hot tables; Intelligent-Tiering for cold. Archive tiers break Delta — files become unreadable.

The transaction log, for real

  • Each commit 0…XXX.json = lines of JSON actions. Checkpoints (*.checkpoint.parquet) every delta.checkpointInterval (default 10) materialise the snapshot.
  • Multi-part v2 checkpoints split logical checkpoints for huge tables — required at millions of files.
  • _last_checkpoint = tiny pointer file. Lost → readers fall back to log scan.
  • Protocol versions gate features. DV / column mapping / type widening bump them; old clients refuse the table.
  • Idempotent writes via Txn(appId, version) — at-most-once on retry.

Concurrency, conflicts, isolation

  • Default WriteSerializable; Serializable opt-in via delta.isolationLevel.
  • File-level conflicts. Disjoint partition writes never collide; overlapping MERGEs retry.
  • MERGE is the contention magnet — mitigate with clustering, DVs, partitioning.
  • Streaming triggers: sub-second creates log explosion; 30s–5min is typical.

File layout

  • Liquid clustering is the modern default. Add/remove cluster columns = metadata-only. GA for Delta (DBR 15.4+); public preview for Iceberg (DBR 16.4+).
  • Hierarchical clustering (DBR 17.1+) — columns in priority order; lower-cardinality columns first maximize data skipping.
  • Partial reclustering with predicates (DBR 18.1+) — OPTIMIZE tbl FULL WHERE <predicate> targets a subset without reclustering the full table.
  • PARTITIONED BY is legacy except for: bounded low cardinality, partition-level ops, external Iceberg reader compatibility.
  • Target file size 128MB–1GB. OPTIMIZE defaults ~1GB; lower for interactive selectivity.
  • Stats on first delta.dataSkippingNumIndexedCols=32 cols — reorder hot predicates first or raise the limit.

Deletion vectors

  • Roaring bitmap files referenced by Add.deletionVector.
  • Mark-on-read; Photon applies natively. External readers need V3+ or UniForm positional-delete mapping.
  • Net win for sparse deletes; periodic OPTIMIZE rewrites to keep DV count bounded.
  • REORG TABLE tbl APPLY (PURGE) physically rewrites files containing DV-flagged rows; use spark.databricks.delta.reorg.purgeMode=rows for targeted large-table purges.
  • On Iceberg v3 tables (DBR 18.0+), deletion vectors are included by default.

Column mapping & type widening

  • id-mode (Parquet field IDs) or name-mode (logical→physical map). Required for RENAME / DROP COLUMN. Bumps minReaderVersion.
  • Type widening lets INT→BIGINT etc. without rewrite; narrowing still rewrites; partial coverage.

Change Data Feed

  • Per-table opt-in. Per-row events in _change_data/ with _change_type.
  • Read via SELECT * FROM table_changes('cat.sch.tbl', startV, endV). Feeds APPLY CHANGES INTO.

Predictive Optimization

  • UC managed tables only (Delta and Iceberg). External tables, OpenSharing recipient tables, HMS tables = your problem.
  • Automates OPTIMIZE / VACUUM / ANALYZE (stats collection) based on small-file count, write rate, query patterns. Beats naive nightly cron by skipping no-ops.
  • Enabled by default for accounts created on or after November 11, 2024; existing accounts being gradually rolled out.

UniForm

  • One Parquet directory, two metadata layers: Delta _delta_log/ + Iceberg metadata/ generated asynchronously each commit. (Hudi was removed; Iceberg is the only supported external format.)
  • Non-Databricks engines (BigQuery, Athena, Redshift, Trino, OSS Spark) read as Iceberg with no copy. OpenSharing recipients can also read via the Iceberg REST Catalog API (public preview).
  • Trade-off: small per-commit metadata cost; some Delta features (DV configs, column-mapping name mode) limit external reader visibility.

Volumes

  • Non-tabular escape hatch. Same permission model as tables. Path /Volumes/cat/sch/vol/....
  • Use for: model artifacts, RAG sources, raw drops before Auto Loader, init scripts, JARs.
  • Not a substitute for tables — no ACID, no stats-based pruning.

Cross-region and cross-cloud

  • Storage + metastore are regional. Cross-region reads pay egress.
  • Delta Sharing is the right cross-region/cross-org primitive — no copy, recipient reads via protocol.
  • True active-active multi-region is not a managed product — roll your own with deep clones or sharing.

Hard limits

  • ~10⁹ files per table soft ceiling — planning latency grows.
  • delta.logRetentionDuration default 30 days — time-travel bounded by it.
  • VACUUM default 7 days exists for a reason; lowering below it requires disabling the safety check.
  • Storage-credential token TTL short; long jobs auto-refresh, raw boto3 from a notebook does not.

Mental model

"Cloud bucket + Delta log + UC permissions, in that order of importance." Bucket holds bytes. Log makes them transactional. UC decides who can see the log. Debug in three jumps: permissions (UC) → snapshot (Delta) → cloud storage (S3/ADLS/GCS).

Anti-patternsWhere you should not use storage like this

  • OLTP working sets in Delta. Use Lakebase; sync to Delta for analytics.
  • High-cardinality PARTITIONED BY. Liquid clustering.
  • Tables on archive storage tiers. Delta needs random reads on the log — archive breaks it.
  • Volumes as tables. No ACID, no stats.
  • Manual file writes into a table dir. Bypasses the log; corrupts the table.
  • One table per tenant for SaaS multi-tenancy. Use row filters in UC.
  • Hive metastore for new work. No UC features. Migrate.
  • Huge blobs in columns. Volumes + path reference.
  • Time travel as backup. Use clone or external backup.
  • Cross-region writes to one hot table. Co-locate writers and storage.

WeaknessesWhere storage does not do well

  • Sub-second write latency isn't a goal. Even Zerobus is seconds end-to-end.
  • Per-row reads on huge tables without good clustering are slow.
  • Schema drift across many writers is brittle.
  • UniForm interop parity is an ops job — feature visibility varies by external reader.
  • Permission-propagation latency — UC changes can take seconds to minutes.
  • External tables outside Predictive Optimization. Bloat without an owner.
  • DV not universal in external readers. Pre-V3 readers may show deleted rows.
  • Storage credential errors are opaque. Audit isn't real-time.
  • No managed multi-region active-active.
  • Big checkpoints for billions of files — v2 multi-part is opt-in and tricky.
  • Volumes have no stats or clustering. Not for SQL.
  • VACUUM is a foot-cannon with 0-hour retention.
