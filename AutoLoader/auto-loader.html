L100What it is

Auto Loader is a Structured Streaming source (cloudFiles) that incrementally ingests new files from cloud object storage into Delta tables. Tracks seen files, infers/evolves schema, scales from few-files to billions.

  • Incremental: only new files per micro-batch.
  • Schema-aware: inference, evolution modes, _rescued_data for malformed rows.
  • Scales: notification mode avoids re-listing.

L200The product surface

  • cloudFiles Spark source. Formats: JSON, CSV, Parquet, Avro, ORC, binary, text, XML.
  • Discovery modes: directory listing (fine to ~10⁵ files; useIncrementalListing deprecated) vs file notification — two sub-variants: classic (SQS/SNS, Event Grid+Queue, Pub/Sub; IAM required) or file events (cloudFiles.useManagedFileEvents=true, DBR 14.3 LTS+; shared queue per UC external location; Databricks-managed; recommended).
  • Schema management: schemaLocation, schemaEvolutionMode (addNewColumns/addNewColumnsWithTypeWidening/rescue/failOnNewColumns/none), inferColumnTypes, _rescued_data column.
  • State: RocksDB-backed seen-files store.
  • Triggers: Trigger.AvailableNow() or continuous micro-batch.
  • Sinks: any Delta destination; commonly LDP ST or foreachBatch.
  • Auth: UC external location credentials preferred.

L300Architecture

Cloud storage path
        │
        ├─[Directory listing]──► periodic LIST                   ──┐
        │                                                          ├──► [Auto Loader micro-batch] ──► Delta sink
        └─[File notification]──► SQS/SNS, Event Grid, Pub/Sub ─────┘                ▲
                                                                                    │
                                                        RocksDB checkpoint (seen files)
                                                        schemaLocation (inferred schema)

Listing mode costs API calls proportional to file count. useIncrementalListing is deprecated; Databricks recommends migrating to file notification mode with file events. File notification — classic consumes cloud events; latency drops to seconds; requires IAM. File notification — file events (cloudFiles.useManagedFileEvents=true, DBR 14.3 LTS+) uses a shared queue per UC external location and is the current recommended approach; no per-stream IAM needed, but does not guarantee file discovery order. Schema files live next to checkpoint; _rescued_data captures unparseable fields.

L400Deep internals

Directory-listing mode

  • Paginated LIST per trigger. useIncrementalListing is deprecated; migrate to file events mode.
  • S3: descend only into new prefixes when partitioned by date.

File-notification mode

Classic: AWS SNS+SQS, Azure Event Grid+Storage Queue, GCP Pub/Sub. Auto-creates or accepts pre-provisioned IDs (cloudFiles.queueUrl, etc.).

File events (recommended, DBR 14.3 LTS+): Set cloudFiles.useManagedFileEvents=true. Shared queue per UC external location; Databricks manages the subscription. No per-stream IAM. Does not guarantee file discovery order — design pipelines accordingly.

One-shot backfill (both modes) via cloudFiles.includeExistingFiles=true.

RocksDB state

  • SHA-256 of seen paths. TTL via cloudFiles.maxFileAge (default 7 days in notification mode).
  • State at checkpointLocation/sources/<source-id>/.

Schema inference + evolution

  • First run: sample N files, infer (JSON with inferColumnTypes for typed cols).
  • Modes: addNewColumns (stream fails after schema update, then restarts), addNewColumnsWithTypeWidening (same plus auto-widens compatible types, e.g., int→long), rescue (route new fields into _rescued_data), failOnNewColumns, none.
  • Type changes are not auto-handled.

Performance tuning

  • maxFilesPerTrigger, maxBytesPerTrigger shape micro-batch.
  • Declare partitionColumns for Hive-style partitions.
  • For binary at scale, parse downstream async.

Exactly-once

  • Auto Loader → Delta is exactly-once: transactional seen-files state, Delta ACID, SS offsets committed together.
  • Broken by allowOverwrites=true or resetting schema location without checkpoint.

Limits / realities

  • One source = one schema location. Two streams can't share.
  • Notification mode requires elevated IAM in default config; pre-provision otherwise.
  • Listing latency grows with file count — switch before pain.
  • _rescued_data opt-in to query — easy to miss.

Mental model

Structured Streaming fileStream for adults: cloudFiles + scalable seen-files state + schema management + cloud-native event integration. Two design decisions dominate: listing-vs-notification and schemaEvolutionMode.

Anti-patternsWhere you should not use Auto Loader

  • Reading a single specific file. Use spark.read.
  • Small static datasets. Use COPY INTO or a one-shot read.
  • Sources that mutate files in place. Default skips re-read; allowOverwrites=true creates duplicates.
  • Two streams sharing one checkpoint. State corruption.
  • Sub-second freshness in listing mode. Use notification mode or Kafka.
  • CDC replacement for databases. Use Lakeflow Connect DB connectors.
  • Heavily nested JSON without _rescued_data discipline. Silent data loss.
  • Cross-cloud sources. Run one Auto Loader per source cloud.
  • Inside LDP, ignoring read_files(). Use the idiomatic SQL helper.
  • Non-Delta sinks. Exactly-once contract hinges on Delta.

WeaknessesWhere it does not do well

  • Listing-mode cost grows with file count. Switch to notification mode.
  • Classic notification IAM friction. Auto-create needs elevated perms. File events mode (useManagedFileEvents=true) eliminates this for UC external location sources.
  • maxFileAge foot-gun. Late-arriving events past 7 days can re-ingest.
  • Sampling-based inference. Rare type variants land in _rescued_data quietly.
  • No multi-tenant schema sharing.
  • No content-hash dedup. Same content, different names = double ingest.
  • Thin XML / fixed-width support. Post-processing required.
  • Partition hints needed. Or partitions become regular columns.
  • _rescued_data easy to forget. Hidden visibility gap.
  • State migration is hard. Listing↔notification usually means fresh checkpoint.
  • CSV inference is weak. Provide explicit schema.
  • Backfill is one-shot. Get includeExistingFiles right on first enable.
