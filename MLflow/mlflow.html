L100What it is

Open-source standard for ML experiment tracking, model registry, agent tracing, and evaluation. On Databricks: preinstalled in DBR, models live in UC, tracing wired into compute and agent runtimes.

  • Tracking: runs (params, metrics, artifacts).
  • Registry: UC models with versions, aliases.
  • Tracing: span-based observability for LLM/agent apps.
  • Evaluation: mlflow.genai.evaluate() + scorers.

L200The product surface

  • Experiments + Runs (params/metrics/tags/artifacts/traces).
  • Models via pyfunc + framework flavors (sklearn, pytorch, transformers, langchain).
  • Registered models in UC with versions + aliases (@production).
  • Tracing: @mlflow.trace + framework autolog (LangChain, OpenAI, DSPy, CrewAI).
  • GenAI evaluation: built-ins (Guidelines, Correctness, Safety, RetrievalGroundedness) + custom @scorer.
  • Logged Models (MLflow 3): persistent model objects tracking lifecycle from prototype to UC-registered version; linked to runs, metrics, params, generation code.
  • Deployment Jobs (MLflow 3): managed evaluate → approve → deploy workflow; UC-governed, activity-logged.
  • Prompt management: version, store, and compare prompt templates across agent iterations.
  • Deploy → Mosaic AI Model Serving.
  • Auto-logging hooks for most frameworks.
  • SDK: Python, TypeScript/JavaScript, R, Java, REST.

L300Architecture

[Training/agent code] → mlflow.* SDK → MLflow tracking server
                                       ├ Experiments/Runs metadata (workspace)
                                       ├ Artifacts (UC cloud storage)
                                       └ Traces (traces store)

Registered models live in UC: catalog.schema.name + versions → consumed by Model Serving / Spark / external

Experiments workspace-local; registered models UC-scoped. Artifacts in your cloud (UC credentials). Lineage propagates from UC tables logged on runs.

L400Deep internals

Run lifecycle

  • start_run creates run; logging targets active run.
  • Nested runs for sweeps.
  • Sealed on end; only tags/description editable.

Models + pyfunc

  • Saved model dir: MLmodel meta, code, weights, python_function wrapper.
  • pyfunc universal; agents use ChatAgent / ResponsesAgent for chat schemas.

UC registered models

  • register_model("runs:/<run-id>/model", "cat.sch.name").
  • Aliases (@production) are pointers; promote = update alias.
  • UC governance applies.

Tracing

  • Tree of spans: function calls, latency, IO.
  • Autolog: LangChain, LangGraph, OpenAI, DSPy, CrewAI, AutoGen.
  • Manual via @mlflow.trace.
  • Queryable by experiment/time/tags/status/latency.

Evaluation

  • mlflow.genai.evaluate(data, predict_fn, scorers=[...]) runs + scores + logs.
  • Built-in scorers wrap LLM judges or deterministic checks.
  • Custom @scorer for domain logic.

Production loop

  • Sample prod traces → label → eval dataset → re-evaluate.

Logged Models + Deployment Jobs (MLflow 3)

  • Logged Models: first-class entity separate from UC registered model versions. Persists the development arc — created during a run, linked to metrics/params/code, promotable to UC. Replaces hunting for "which run ID held the best artifact."
  • Deployment Jobs: pipeline object sequencing evaluate → approve → deploy. UC-governed; each transition is activity-logged. Formalises the alias-promotion ceremony.

Prompt management

  • Store prompt templates in MLflow with versions and aliases.
  • Compare prompt versions against an eval dataset before deploying.
  • SDK-accessible and surfaced in the MLflow UI.

Autolog gotchas

  • Custom training loops skip autolog.
  • Use framework callbacks (PL, HF Trainer) for full control.

Limits / realities

  • Search paginated.
  • Artifact storage in your cloud; cleanup is on you.
  • Trace storage cost → sample in prod.
  • Version-pinned autolog.
  • MLflow 3 tracing model differs from 2.x.

Mental model

Connective tissue between training and serving + observability for agents. MLflow 3 makes agent tracing + eval first-class; UC owns model identity.

Anti-patternsWhere you should not use MLflow

  • Logging huge artifacts every run. Log references.
  • Sub-second serving from MLflow directly. Use Model Serving.
  • No-sample prod traces. Fills storage fast.
  • Flat thousand-sibling sweeps. Use nested runs.
  • Every dev model in prod catalog.
  • Custom pyfunc when a flavor exists.
  • Manual trace of autologged frameworks.
  • Experiments as compliance audit. Use UC audit.
  • PII in logged params. Redact first.
  • Local-path artifacts. Use UC volumes.

WeaknessesWhere it does not do well

  • Search across many experiments slow.
  • Trace storage cost at scale.
  • Autolog version pinning fragility.
  • Alias UX is basic.
  • LLM-judge scorers cost a lot.
  • Cross-experiment compare manual.
  • Distributed training instrumentation uneven.
  • Notebook trace UX is awkward.
  • Limited custom UI on trace viewer.
  • No scorer registry; bake into wheels.
  • Per-region models.
  • Prod→eval wiring is manual.
