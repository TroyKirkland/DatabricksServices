L100What it is

Open exchange for data products, AI models, notebooks, and MCP servers. Delivery via OpenSharing protocol (built on Delta Sharing); UC-native for Databricks consumers. Browsable publicly without a workspace.

  • Open via OpenSharing/Delta Sharing protocol.
  • Data + AI + notebooks + MCP servers (tabular and non-tabular volumes).
  • UC-native one-click foreign catalog; MCP servers install as workspace connections.

L200The product surface

  • Provider page + listing types: datasets (tabular UC catalogs + non-tabular Volumes), AI models, notebooks, MCP servers.
  • Consumers: any workspace or OpenSharing/DS-compatible client; public browsing requires no workspace.
  • Access models: free / free-with-approval / private exchange / paid (incl. Universal Commit Drawdown).
  • Get-access flow creates foreign UC catalog (or workspace connection for MCP servers).
  • Embedded sample notebooks.
  • Discovery: category/industry/free-paid/region filters.

L300Architecture

[Provider] UC tables/models/notebooks/volumes/MCP + share + listing → Marketplace catalog
                                              ↓ approval
[Consumer] foreign UC catalog (OpenSharing/Delta Sharing-backed) → queries / uses
           MCP server → installed as workspace connection → agent tools

Listings = OpenSharing shares + metadata + approval workflow. Non-tabular data delivered via Volumes. MCP servers install as connections.

L400Deep internals

Provider mechanics

  • Profile + listings each referencing one or more shares.
  • Metadata: tags, industry, geography, schema preview.

Consumer mechanics

  • Browse → request → instant or approved.
  • Auto-creates foreign UC catalog via CREATE CATALOG ... USING SHARE.
  • Audit via outbound logs (provider) + access audit (consumer).

Paid listings

  • Billing via cloud marketplace (AWS/Azure/GCP).
  • Usage metering configurable.
  • Universal Commit Drawdown: up to 10% of Universal Commits usable for eligible third-party purchases.

Notebooks, AI models + MCP servers

  • Notebooks bundled as samples/tutorials.
  • Models = UC registered models shared via OpenSharing/Delta Sharing for D2D.
  • MCP servers: tools and APIs for agents; installed as workspace connections.
  • Non-tabular data: delivered via Volumes (files, not Delta tables).

Search + discovery

  • Categories, filters, featured placement.

Auditing

  • Provider: system.access.outbound_*.
  • Consumer: system.access.audit.

Limits / realities

  • Pre-signed URL revocation isn't instant.
  • Provider egress scales with consumer usage.
  • Schema changes affect all consumers.
  • Marketplace search shallow.
  • Cross-cloud paid billing awkward.
  • Some UC features (row/col policies) over sharing have caveats.

Mental model

"Discovery layer on OpenSharing/Delta Sharing + optional billing." Marketplace adds catalog, search, approval flow, MCP server distribution, billing (incl. Universal Commit Drawdown) — atop Delta Sharing.

Anti-patternsWhere you should not use Marketplace

  • Single-org sharing. Use UC + Delta Sharing direct.
  • Real-time data. Seconds/minutes latency.
  • Cross-tenant compute isolation. Use Clean Rooms.
  • Frequent schema-changing listings.
  • Reverse-distribute outputs at scale.
  • OLTP-style data exchange.
  • PII without legal frameworks.
  • Models with tightly coupled consumer infra.
  • Enterprise sales-led products. Use direct DS.
  • Listings without samples/docs.

WeaknessesWhere it does not do well

  • Basic search.
  • Inherited DS revocation lag.
  • Cross-cloud paid billing awkward.
  • No listing versioning.
  • Limited provider discovery analytics.
  • Consumer query cost not surfaced upfront.
  • Provider egress visibility weak.
  • Notebook updates = replace.
  • Cross-listing deps not modelled.
  • License attestation text-based.
  • Per-region listings.
  • Rigid paid pricing model.
