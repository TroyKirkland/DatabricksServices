L100What it is

Databricks' vector database. Define an index over a UC column (text or pre-computed embeddings); Databricks keeps it in sync with the Delta source; query by similarity at low latency.

  • UC-native indexes; governed and lineage-tracked.
  • Delta-synced embeddings.
  • Hybrid: vector + metadata filters + optional BM25.

L200The product surface

  • Endpoints: Standard (fast, costly) vs Storage-optimized (cheap, slower).
  • Index types: Delta Sync (compute or self-managed embeddings) + Direct Vector Access + Full-Text Search Index (Beta) — BM25 keyword search, no embeddings required; storage-optimized + triggered sync only.
  • Embeddings via FMAPI (gte-large-en) or external endpoint.
  • Query API: similarity_search(text|vec, k, filters).
  • Filters: SQL-like over declared metadata cols.
  • Hybrid: vector + keyword via Reciprocal Rank Fusion (RRF); result cap 200 (ANN up to 10,000).
  • SDK / REST / LangChain / DSPy integrations.
  • Service principals: up to 100 ms faster per-query vs PAT in production.

L300Architecture

Sync pipeline tails CDF, recomputes embeddings for changed rows. ANN (HNSW-style) for vectors; filters alongside.

L400Deep internals

Index types

  • Delta Sync + Compute Embeddings: Databricks reads + embeds + stores.
  • Delta Sync + Self-Managed: source already has embedding column.
  • Direct Vector Access: SDK write; not Delta-bound.
  • Full-Text Search Index (Beta): BM25 keyword index on text columns; no embeddings; storage-optimized endpoints + triggered sync only.

Sync semantics

  • Triggered (schedule/on-demand) or continuous (CDF-tail).
  • Backfill on create.
  • Embedding col change → recreate.

Embeddings

  • Embedding endpoint = Model Serving endpoint; per-token cost.
  • Auto batch + rate-limit-aware.
  • Dim fixed at create; can't change.

Query path

  • Resolve index → apply filters pre-rank → ANN → top-k with score + metadata (up to 10,000 results).
  • Hybrid: vector + keyword merged via RRF; capped at 200 results.

Filters

  • =, <, >, IN, AND/OR/NOT.
  • Filterable columns declared at create.
  • Heavy exclusion → may need larger k.

Permissions

  • UC: SELECT (query), MANAGE.
  • Endpoint service identity reads source data.

Performance

  • Standard: tens of ms p50; up to ~320M vectors at 768 dims.
  • Storage-optimized: 1B+ vectors at 768 dims; 10–20× faster indexing; ~250 ms extra query latency; no continuous sync.
  • Scales with replicas; per-endpoint concurrency cap.
  • Service principal auth: up to 100 ms faster per-query than PAT.

Cost

  • Endpoint hours + embedding compute (rows × model cost) + storage.

Limits / realities

  • One embedding model per index.
  • Dim fixed at create; max 4096 dimensions.
  • Delta + UC required for sync indexes.
  • Standard: ~320M vector ceiling; storage-optimized: 1B+.
  • Up to 50 indexes per endpoint.
  • Hybrid result cap: 200 (ANN: 10,000).
  • Storage-optimized: no continuous sync.

Mental model

"Semantic indexes on UC tables, synced, filterable, hybrid-scorable." Differentiator: data + embeddings + ACL + lineage in one place.

Anti-patternsWhere you should not use Vector Search

  • Tiny indexes. pandas + cosine wins.
  • Storing source docs in the index. Reference by ID.
  • Exact keyword needs. Use full-text / LIKE.
  • Frequent dim changes.
  • Sub-ms latency.
  • Existing external vector store. No migration tooling.
  • General KV lookup. Use Lakebase.
  • BYO GPU embeddings outside Model Serving.
  • Continuous sync on high-churn dimensions.
  • Multi-tenant in one index. One per tenant.

WeaknessesWhere it does not do well

  • Recreate on schema/dim change.
  • Embedding cost dominates large indexes.
  • Filter selectivity-recall trade-offs.
  • RRF hybrid scoring non-configurable per-query; cap of 200 results.
  • No native reranking.
  • Internal ANN format only.
  • Per-endpoint concurrency caps.
  • Storage-optimized latency.
  • Distance-metric switches limited.
  • Sync lag visibility limited.
  • Filter cols declared at create.
  • No native cross-region.
