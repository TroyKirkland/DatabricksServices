L100What it is

Managed Postgres on Databricks for OLTP alongside the analytical lakehouse. Two tiers: Provisioned (always-on production Postgres) and Autoscale (scale-to-zero, branchable, instant-restore).

  • Postgres-compatible wire protocol; standard tooling works.
  • UC-integrated: governance, lineage.
  • Sync with Delta: bi-directional patterns.

L200The product surface

  • Instance: Provisioned (instance class + storage) or Autoscale (CUs + storage).
  • DB / schema / table — standard Postgres.
  • Autoscale: scale-to-zero, branching, instant restore.
  • Provisioned: HA + automated backups + PITR.
  • Synced tables (Delta → Lakebase) via CDF.
  • Lakehouse Federation back into UC for analytics.
  • Access via Postgres conn string + UC creds.

L300Architecture

[App/agent/notebook] → Postgres wire → [Lakebase instance]
                                          ├ Provisioned: dedicated Postgres + HA + backups
                                          └ Autoscale: scale-to-zero, branchable, CoW storage
                                          ↓
                                       [Tables: synced from Delta or native]
                                          ↓ (optional) Federation back into UC

Two tiers, different ops profiles. Synced tables are the standard low-latency-reads-from-Delta pattern.

L400Deep internals

Provisioned

  • Managed Postgres cluster; instance class + storage sizing.
  • HA primary+standby; auto failover.
  • PITR via base + WAL retention.
  • Curated extensions (pgvector + others).

Autoscale

  • Separation of storage + compute.
  • Branching = CoW reference at branch time; writes diverge.
  • Scale-to-zero with seconds resume.
  • Instant restore = pick timestamp; new branch immediately.

Synced tables (from Delta)

  • PK matches Delta source.
  • CDF-driven inserts/updates/deletes.
  • Seconds latency.
  • New columns auto-flow; renames/type changes need care.
  • Same engine as Feature Engineering online tables.
  • ai_search on synced tables (Beta Sep 2026): ai_search SQL function can search Lakebase synced tables — semantic search without a separate Vector Search index.

UC integration

  • Instance is a UC object; UC governs permissions.
  • Connection identity = SP for app access.
  • Federation re-exposes Lakebase tables as UC tables (analytics).

Performance

  • Provisioned: instance-class dependent.
  • Autoscale: cold-resume seconds; warm = Postgres expectations; branching = metadata-only.
  • Pool connections (pgbouncer or app pools).

Use cases

  • App backend (Databricks Apps state).
  • Agent memory / sessions.
  • Online feature serving.
  • Operational dashboards.
  • Branched envs for dev/preview.
  • Semantic search on synced tables via ai_search (Beta Sep 2026).

Limits / realities

  • Curated extensions only.
  • Synced tables one-way; bi-directional needs custom logic.
  • No native cross-region.
  • Connection caps per tier.
  • Tier migration not in-place.
  • Long-running diverged branches cost.

Mental model

"OLTP companion to the lakehouse." Provisioned = classic managed Postgres + UC; Autoscale = serverless Postgres (scale-to-zero, branch, restore) for AI/app workloads.

Anti-patternsWhere you should not use Lakebase

  • Heavy analytical queries. Use DBSQL on Delta.
  • Multi-TB OLAP.
  • Primary copy of analytical source-of-truth. Land in Delta first.
  • Whole-table replication to Lakebase "just in case".
  • Cross-cloud / cross-region heavy use.
  • Long-running analytics-style transactions.
  • Unbounded app connection growth. Pool.
  • Huge BLOBs. Use UC Volumes.
  • Forever-on dev branches without budget.
  • Hardcoded Postgres creds bypassing UC.

WeaknessesWhere it does not do well

  • Curated extension set only.
  • One-way synced tables.
  • No native cross-region.
  • Tier migration effort.
  • Connection caps without pooling.
  • Synced-table schema evolution gaps.
  • Autoscale cold start.
  • Branch storage cost.
  • PITR retention limits.
  • Federation latency analytics.
  • Lagging Postgres feature parity.
  • UC vs Postgres role duality.
